# 验证范围

## 既有 0.2.2 基线

Windows 上已执行 20 项核心/协议/预览测试和 3 项实际 MCP EXE 测试，均通过。实际便携 EXE 使用两个独立 MCP 进程验证过文件变化、独立确认、回合交接和消息收发，测试子进程不依赖系统 Node/npm。

布局回归另通过实际 EXE 提供的页面测量：长 Markdown 在 1440×900、1440×700、1280×960、1100×760、390×844，以及长代码、CSV、图片、PDF、长文件名和改动差异，共 11 个场景。修复前约 400 px 重叠，修复后均为 0；左栏保持位置，窄屏无页面横向溢出。

这些历史结果不代替后续提交的验证。当前提交的自动检查以 [Windows CI](https://github.com/Meowcoa/tongpin-workspace-observer/actions/workflows/ci.yml) 为准，测试定义位于 tests/。CI 从干净检出安装依赖、执行源码边界检查、测试、构建、实际 MCP EXE 测试及实际便携 EXE 验证。

## 验证约定

- 夹具只写入仓库 `.work/` 的一次性目录，不修改用户真实项目或正式数据。
- 目录和工具数来自真实注册/运行结果，不使用演示结果代替协议调用。
- 修改消息、身份、租约或游标时，应验证重启和不同客户端间的隔离。
- 修改滚动或尺寸时，除独立预览页，还须验证改动记录里的长预览和下方客户端区。
- CI 通过不等于所有模型宿主或所有预览格式均已验证；真实 AI 会话、长期运行、网络盘、更多 DPI 和编解码器需另行记录。

工作流按需手动运行时会上传构建产物；构建包未代码签名。
