# 同频 0.2.1：接入可见与界面登记

本版为客户端页增加“全部 / 未登记 / 已登记”筛选和“一键登记”。连接 MCP 页面所在的右侧内容区独立滚动，左侧导航保持在视口内；切换页面时右侧回到顶部。

## 接入和登记

1. 在“连接 MCP”为每个 AI 生成专属配置并让目标工具实际连接。
2. 服务收到已鉴权的 MCP 初始化握手后记录接入身份。客户端不必先调用 register_client，便会以“未登记”出现在“AI 客户端”页。
3. 用户点击该行“一键登记”，身份便与当前工作区绑定。原 MCP 连接下一次调用就能取得自己的 client_id，无需断开重连。
4. AI 仍可调用 register_client 更新自己的显示名，不会因界面已登记而产生第二个客户端，也不重置已读位置。

仅生成配置不会伪装为已成功接入；未选择工作区时可查看接入记录，选择工作区后才可登记。接入记录和登记结果会持久保存。登记状态不代表持续在线，绿色只表示两分钟内收到请求，关闭连接后也保留历史接入记录。

## 身份与边界

接入观察位于独立凭据鉴权之后，名称来自用户命名的专属身份或 MCP 宿主自报信息，不信任工具参数里的 client_id。原有 credential_clients 绑定规则不变。

新增 mcp_presence 表仅保存凭据 ID、宿主名称、握手时间和最近请求时间，不保存令牌正文。原有客户端、事件、消息与读取位置不删除。

GET /api/clients 返回登记状态、凭据 ID、可登记状态及原客户端信息。POST /api/clients/register 输入 workspace_id 和 credential_id，仅管理界面会话可调用；MCP 凭据不能调用。服务校验当前工作区、实际接入记录及撤销状态。重复登记返回原绑定，不会替客户端确认变化、读取消息、申请回合或调用模型。

## 更新

先完整退出旧版同频，再运行 0.2.1。在 WorkBuddy 中将 workspace_observer 重新连接一次，让新版记录握手，然后到“AI 客户端”点击“一键登记”。不必把登记命令再发给 AI。

已有 0.2.0 专属配置可继续使用。本版已用从旧交付包提取的真实 0.2.0 MCP EXE 验证：连接 0.2.1 后端、显示未登记、经界面登记、原连接继续查询变化。也可从新版重新复制配置或导出插件包。

原有双模式、消息和文件预览协议继续有效，MCP 工具数量仍由真实注册生成，目前为 12 个。详细协作边界见 COLLABORATION.md。
