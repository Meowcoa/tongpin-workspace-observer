# 同频 0.2.0：双模式协作与本地消息

依据用户提供的《同频双模式协作与 AI 通信改造说明 v2》实现。本文说明实际行为，不代表原始 v0.2 构想中的其他功能也已完成。

## 使用与升级

普通用户运行 Releases 中的 Windows 便携 EXE。默认同时模式，桌面数据在 `%LOCALAPPDATA%/TongpinObserver/data`，新安装不预设工作区。预览、监听、快照与独立文件确认继续可用。

从旧版升级时先退出旧程序，再运行新版；到“连接 MCP”为每个 AI 分别生成专属身份、复制配置或导出接入包，然后重新加载 AI 客户端。旧的共享 HTTP MCP 密钥不能直接调用新工具；旧版独立 MCP 程序需要替换为新版配置中的程序。

专属配置带有非秘密的 `--client <profile-uuid>`，桥接器从当前数据目录的 `client-credentials/<profile-uuid>.key` 读取自己的凭据。不同 AI 不应共用同一份专属配置。配置、导出包和页面不包含密钥正文。换电脑、用户或数据目录应重新生成。

未带 `--client` 的配置仍可启动，但每个桥接进程会获得一个新的独立临时身份；重启后需要重新登记，不自动继承旧身份的已读位置。正式协作请使用专属身份。旧客户端的记录不会删除，可以在生成身份时由本地用户选择“恢复旧客户端读取位置”；模型不能自行指定别人的旧 client_id。

## 身份模型

采用 v2 优先方案，不采用“由模型传入 client_id”的降级方案。

- `mcp_credentials` 只在数据库保存专属令牌的 SHA-256 摘要。
- HTTP `/mcp` 每次按 Bearer 凭据解析身份，再通过 `(credential, workspace)` 绑定客户端；不以显示名或工具参数决定发送者。
- `register_client` 创建/更新当前凭据对应的客户端。`resume_client_id` 只能与本身份已经绑定的客户端一致。旧记录的绑定只能通过已鉴权的管理界面操作。
- 原有 `mcp.key` 仅供本地桥接初始化 `/bridge/session` 使用，只能产生一个新身份，不能选择或恢复其他身份，也不能直接调用 MCP。
- 撤销身份立即阻止其后续 MCP 调用，并移除其回合和排队记录，保留客户端和消息历史。
- UI 会话、桥接初始化凭据、各客户端 MCP 凭据的权限分离。MCP 凭据不能调用管理 API、原始文件预览、强制结束回合或清理消息。

这是同一 Windows 用户下的本地协作工具；它不提供不同操作系统用户之间的文件权限隔离，也不阻止拥有本机数据目录读取权限的程序读取凭据文件。

## 工具协议

实际工具目录由构建脚本通过真实 `makeMcp()` 和 MCP SDK 协议生成。测试、桥接发现和打包验证从真实目录取工具数，不硬编码数量。本版实际注册 12 个工具。

原有工具：`get_workspace_status`、`register_client`、`get_changes`、`get_change_detail`、`ack_changes`、`report_activity`、`list_clients`。

原有变化/确认/活动工具可以省略 `client_id`，服务端从凭据确定；为了兼容既有调用格式仍接受这个字段，但传入时必须等于自身身份。状态返回 `session_client_id`、设置、协作状态和消息用量；公共状态和客户端列表不公开租约。

| 新工具 | 输入 | 结果与语义 |
| --- | --- | --- |
| `request_turn` | `workspace_id?` | 同时模式 `not_required, allowed=true`；依次模式 `holding` 或 `waiting`。只有本持有人收到 `lease_id`、到期时间；等待者收到队列位置和轮询建议。再次申请可用同一租约续约。 |
| `finish_turn` | `workspace_id?`, `lease_id?` | 持有人必须匹配当前租约；等待者退出队列；已经释放时幂等。不隐式确认变化或消息。 |
| `send_message` | `workspace_id`, `recipient_client_id?`, `reply_to_message_id?`, `type`, `subject`, `body`, `related_paths?`, `related_change_ids?` | 返回消息 ID、工作区内单调序号、服务端填写的发送者与创建时间。收件人为空表示广播。 |
| `get_messages` | `workspace_id`, `after_seq?`, `limit?`, `epoch?` | 返回发给自身的私信和他人的广播，以及 `cursor_next`、`has_more`、历史缺口和代次。可以更新 delivered，不自动更新 ack。 |
| `ack_messages` | `workspace_id`, `through_seq`, `epoch?` | 只确认不超过本人 delivered 的序号，单调推进自己的 ack，与文件变化确认分开。 |

五个新工具严格拒绝额外的 `client_id` / `sender_client_id` 等未知字段。消息类型为 `question`、`review_request`、`handoff`、`result`、`notice`。主题最多 200 字符，正文最多 16384 字符；关联路径、变更各最多 50 项。路径拒绝绝对路径、盘符、ADS 和 `..` 段；收件人、回复和变更引用必须在同一工作区，不能回复无权读取的私信。

例如依次模式获准时：

```json
{"mode":"sequential","state":"holding","allowed":true,"lease_id":"本回合随机 UUID","expires_at":"ISO-8601","queue_position":0}
```

每条读取到的消息带 `untrusted_content: true` 和不可信数据警告。查询不会删除消息。默认不把自己的广播再作为自己的未读。私信过滤后会返回有效分页游标，避免被不可见消息卡住分页；游标跳过不属于自己的消息不代表可以读取其正文。

## 回合与设置

默认：同时模式，租约 900 秒，保留 30 天，消息配额 10240 KiB，客户端最小发送间隔 2 秒。租约可设 60–7200 秒。设置以“默认值 + 已保存字段”合并读取，管理 API 严格拒绝未知字段和非法值。

所有回合变更位于 `BEGIN IMMEDIATE` 事务中，并由部分唯一索引保证每个工作区最多一个持有人。首次入队时分配工作区单调 `queue_seq`；重复轮询保留原序号和请求时间。持有人为第 0 位，等待位置为活跃等待者中序号小于自己的数量加 1。即使时间戳相同也按入队序号稳定排序。

持有人超时后在下一次申请中回收。等待者建议每 30–60 秒轮询，超过 180 秒未轮询会被清理。没有持有人时，只有最早的活跃等待者再次申请才能获准，后来者不能插队。状态查询按当前时间展示已过期回合，不为展示而修改数据库。

只有协作模式实际改变时才清空所有工作区的回合和队列。修改保留期、租约或消息设置不会清空当前回合；既有租约到期时间在持有人下一次续约时按新配置更新。

用户可以在“协作设置”确认后强制结束当前回合。`POST /api/turn/force-release` 只接受本地 UI 会话，输入 `workspace_id`；保留等待队列，记录时间、客户端和操作类型，不记录密钥或消息正文。不作为 MCP 工具提供。

## 消息、配额与清理

消息持久保存在 `messages`。`message_cursors` 主键为 `(workspace_id, client)`，发送间隔记录也按工作区和客户端保存，重启不重置限速。

消息配额按主题和正文的 UTF-8 字节数计算，超额拒绝新消息，不静默丢弃，也不自动删除旧消息。界面显示用量及最近一次配额拒绝状态，可以提高配额或经确认清理当前工作区全部消息。发送过快时返回具体需要等待的秒数。新增配额后不追溯删除现有消息。

消息与文件变化均按 `retention_days` 清理，但使用各自表和历史区间。手动清理消息只删除消息正文，保留文件变化、客户端和单调消息序号；落后读者会收到 `history_gap`，核对当前协作状态后可从 `oldest_available_seq - 1` 恢复保留区间。

UI“协作消息”是本地管理视图，可查看当前工作区最近 100 条广播及私信，但不推进任何 AI 的消息游标；消息正文始终以转义文本显示。

## 迁移与历史代次

新增表和索引采用加法迁移，不 destructive 重建旧库，不删除已有事件、快照、客户端或设置。旧三字段设置读取时补齐新默认值。

`workspaces.epoch` 改变时，由数据库触发器清空所有工作区的回合/队列和消息游标，旧租约失效；消息本身保留并按保留策略独立清理。旧客户端需重新登记当前代次，文件 ack/delivered 归零，再检查基线；消息游标从零重新建立，保留区间外仍报告历史缺口。专属凭据与客户端绑定不因此被其他身份接管。

当前一次只监控一个项目。协议保留 `workspace_id`，旧项目与新项目的客户端绑定、回合和消息游标分开；工具拒绝使用非当前工作区来申请回合或收发消息。

回滚源码请使用对应 Git 标签，运行中版本降级前应先退出。较旧版本可能不认识新协议；重要历史应先完整退出程序再复制用户数据目录，避免遗漏运行中的 SQLite WAL 数据。

## 验证与边界

`npm test` 覆盖旧库、设置、并发 FIFO、租约、过期展示、人工释放、身份冒用、私信隔离、消息确认/分页、限速/配额/清理、重启、历史代次、HTTP/STDIO 和预览回归。`npm run test:desktop` 使用真实独立 MCP EXE，子进程 PATH 不含 Node/npm。`scripts/verify-packaged.mjs` 对实际便携 EXE 执行回合交接、消息收发和文件变化验证。

本机安装的 electron-builder 26.18.0 在 `unpackDirName=true` 时不生成共享目录定义，因此本项目显式设置该值，使便携程序使用每次启动独有的 `$PLUGINSDIR/app`。此次曾复现共享目录被其他实例清理后的 `Invalid file descriptor to ICU data received`。该版本实际代码与[官方选项说明](https://www.electron.build/docs/api/app-builder-lib.interface.portableoptions/#unpackdirname)中的布尔值描述不同，行为以生成的 NSIS 脚本和实际重复启动检查为准。

回合不是操作系统级文件锁，不能阻止不遵守协议的 AI 或编辑器修改文件；不自动合并冲突。消息不会主动调用模型或唤醒空闲 AI；需要 AI 自行轮询。尚未逐一验证各 AI 宿主的插件安装界面，也未完成原始基础方案中的 check_files、hooks、净变化合并、快照压缩或大规模/网络盘/耐久性验证。程序未代码签名。
